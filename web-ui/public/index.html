🔌 Simulate model outage: how failover works
  1. The toggle breaks the call on purpose. It sends x-simulate-outage: primary. Apigee then calls the chosen model on a path that doesn't exist (same host), so it returns HTTP 404. Nothing changes on the real backend.
  2. Apigee catches the error. Instead of returning the error, it retries once on the tier's backup Gemini model on Vertex AI.
  3. The caller still gets an answer. You'll see the 🔁 Failover banner, a FAILOVER tag on the routed model and an amber Model Call step. The cost is for the backup model.

ⓘ Real outages trigger the same failover; the toggle just makes one happen on demand. Bad requests (400 / 413) are not retried, and if the backup also fails the caller gets a generic error.
